**Baseline test caveat (root-caused; fix scheduled Phase 2/5).** Under Windows default `cp1252`,
`tests/synthetic/test_property_invariants.py::test_lkb_loglogit_bounded_or_nan` can spuriously fail.
It is **not** a numeric defect:
- passes in isolation; Hypothesis `@given` with no fixed seed (different examples per run);
- a **1.79 M-point** brute-force grid over the whole declared space (gEUD 1–80, TD50 10–80, γ 0.5–6) plus
  edge cases → **zero [0,1] violations**; the LKB log-logistic is analytically bounded;
- real disruptor: `UnicodeDecodeError (cp1252, byte 0x8f)` in a subprocess **reader thread** —
  `tests/test_integration.py`, `test_ntcp_analysis.py`, `test_tcp_analysis.py`, `engine/tests/test_outputs.py`
  call `subprocess.run(..., text=True)` **without `encoding=`**, so the CLI's Unicode console output
  (σ ✓ — °) fails to decode. `PYTHONUTF8=1` → suite fully green. (The existing release
  `VERIFICATION_REPORT` already prescribes `$env:PYTHONUTF8="1"`, confirming this is known.)
