rbGyanX Version 1.5.2
Release Identifier: FINAL_V3.2
Release Date: 2026-11-14
Type: Production Release

Two identifiers are in use and they mean different things:

  Software version   1.5.1        semantic version of the codebase (engine + GUI)
  Release identifier FINAL_V3.2   generation of the validation/analysis programme that this
                                  release freezes (V1 -> V2 -> V3 -> V3.1 -> V3.2)

The release identifier is deliberately UNCHANGED at FINAL_V3.2. The 1.2.x, 1.3.x and 1.4.x
lines add the AI assistant and repair software defects; they introduce no new scientific result
and rerun no analysis. The analysis programme this release freezes is therefore the same
generation 1.1.0 froze, and saying otherwise would imply a revalidation that did not happen.
What changed is software, and it is described in CHANGELOG.md.

1.5.2 IS A PATCH RELEASE. It repairs four defects. Three change no reported number: they restore
or correct what the output could show. THE FOURTH DOES CHANGE ONE -- the Monte Carlo NTCP bands --
and it matters, so it is stated first:

  The uncertainty bands beside each NTCP were computed from the physical dose-volume histogram
  while the estimate itself was computed from the EQD2 one. The EQD2 correction of 1.5.1 gave each
  row two histograms and updated the estimate's call site but not the band's. Every uNTCP mean, SD
  and percentile reported by 1.5.1 therefore belongs to a different dose basis from the number
  printed beside it, and the band must not be quoted as that estimate's interval. The bands now
  follow the estimate, and each row records which basis was used. The NTCP point estimates do not
  change.

The other three are in what the output could show rather than in what it computed:

  A target whose TCP is refused now keeps gEUD_gy. gEUD is a function of the dose-volume histogram
  and the site's volume exponent alone, so refusing a TCP never needed to discard it. Every
  refused target previously reported NaN for a computable value. Scored targets are unaffected:
  the gEUD is computed once and the gEUD-based TCP is evaluated from that same number.

  The run manifest's prescription-table record is cumulative. It counted only the lookups the
  process that wrote it had performed, so a run resumed in batches reported its last batch as
  though it were the whole cohort, in the same file whose per-patient status was cumulative.

  A supplied prescription is reported as the source of the dose level it sets. The row named the
  DICOM field the level had been matched against, which is not where the value came from; the
  field matched now has a column of its own.

No analysis was rerun to produce this release, and the release identifier stays FINAL_V3.2.

1.5.1 IS DIFFERENT IN ONE RESPECT, AND IT MATTERS. Up to and including 1.5.0 these lines also
altered no reported number. 1.5.1 does: defect #63 means every release up to 1.5.0 computed NTCP
on physical dose whenever the plan sat within 0.3 Gy of 2 Gy per fraction -- conventional
fractionation. The dose-volume histogram is now converted to EQD2 before the NTCP models see it,
so gEUD and every NTCP computed from it change. Measured on one arm of 116 patients, the gEUD
median moved by between -5 % and -37 % depending on the organ. The reported physical dose
statistics are unchanged. The release identifier still does not move: the analysis programme is
the same, and what changed is a defect in the software that implements it.

1.5.1 is a PATCH release. It repairs four defects found by review of the 1.5.0 evidence, one of
which (#63) changes every NTCP the software reports. It adds no new scientific result and reruns
no analysis of its own; the cohort rerun that accompanies it is a re-measurement of the same data
with the defect fixed. The release identifier stays FINAL_V3.2 for the reason given above.

What changed, in the order it matters:

  Scope. The repository now contains general software only, usable by anyone with their own data.
  The versioned record of one study's analysis (analysis/, 35 files) and the material specific to
  that study were removed. They remain retrievable at the v1.4.0 tag and in the archive deposited
  for that release. A consequence worth stating plainly: THIS RELEASE COMPUTES NO CT RADIOMIC
  FEATURE. The IBSI-1 digital-phantom benchmark measured 56 of 63 reference features reproduced,
  and that is a statement about 1.4.0, where the code shipped - not about this release. See
  docs/KNOWN_LIMITATIONS.md.

  Parameters. Default NTCP parameters are now sourced to published fits, organ by organ, with the
  source and endpoint recorded beside each value.

  Defects that changed written numbers. gEUD dropped zero-dose bins, so a negative exponent with an
  occupied 0 Gy bin gave a wrong answer; geud_a held n instead of 1/n; a DICOM read through the
  obsolete `dicom` package returned NaN everywhere without raising, and a run completed and wrote a
  full tree of them. Each is fixed with a test that fails on 1.4.0 and passes after.

  A measured limitation that is NOT fixed. The DVH end-caps structure volume but not the dose
  range, so Dmax_gy is low and Dmin_gy high by slice_thickness/2 x the local dose gradient - 1.5 Gy
  at a 3 mm slice and 1 Gy/mm, always in the optimistic direction. Dmean_gy and gEUD are unaffected
  to within 0.5 Gy. Dose sampling sits in dicompyler-core, and changing it would alter every DVH
  this project has produced, so this release documents and bounds the bias rather than changing the
  convention. docs/KNOWN_LIMITATIONS.md gives the magnitudes and the organs it matters for.

  Documentation that claimed what was not there. Two capability claims and twenty-one references to
  removed paths were corrected, including two dead links on the front page and a pointer written
  into every generated run report.

  Testing. The CI matrix job ran 65 of 134 test files; it now runs the default selection and
  excludes only marked tests. The first run on the widened selection found five real failures in
  files the matrix had never executed.

1.4.0 is a MINOR release. It repairs software defects and adds no new scientific result: every
headline value in the evidence package produced against this code is a measurement rather than a
change, and no analysis was rerun to produce this release. The
release identifier stays FINAL_V3.2 for the reason given above - the analysis programme generation
is unchanged, and moving it would imply a revalidation that did not happen. What changed is
provenance (site, site_confidence and dvh_mode now populated on every cohort row instead of
none), structure-name laterality (a fuzzy match that invented a side is now refused), output
determinism, and LLM-assisted structure mapping that proposes and never decides. See CHANGELOG.md.

Note on the evidence artefacts: the three AFTER cohort runs executed at commit 7f42c4d0, which
predates this bump, so their run_manifest.json files carry the embedded string 1.3.0. That is not
fixable retroactively and was deliberately not rerun. THE COMMIT SHA RECORDED IN EACH MANIFEST IS
THE AUTHORITATIVE IDENTIFIER of what produced that artefact, not the embedded version string.

The 1.3.0 rationale, kept as history:

1.3.0 was a MINOR release, not a patch, because it changed three documented behaviours. Suspected
PHI bound for a remote AI provider is now blocked outright instead of warned about and sent; a
site whose TCP parameters are missing or technique-specific now resolves correctly or raises
instead of silently substituting a near match; and the expression calculator no longer evaluates
user input with eval(). A caller relying on any of the old behaviours will break, which is what
makes this a minor rather than a patch release. See the Changed / Breaking section of
CHANGELOG.md.

Supported Python: 3.10-3.12, which is exactly the matrix CI tests on Linux and Windows. Note that
this is NOT the interpreter the published study analysis ran on: that analysis used Python 3.14.2 on
Windows with its own package set, because it drove the engine directly rather than the installed
rbgyanx distribution. Both records are accurate and they describe different environments; neither
should be edited to match the other. The analysis-side record is
analysis/FINAL_ANALYSIS_CODE_MANIFEST.json, which is NOT in this repository: analysis/ was removed
in v1.5.0 as study-specific material and is retrievable at the v1.4.0 tag and in that release's
deposited archive.

FINAL_V3.2 supersedes FINAL_V3.1. It adds no new scientific result: every headline value is
unchanged and was independently verified before this release was built. It exists to close four
release blockers found in the final completion audit:

  B1  the analysis code that produced the reported results is now versioned, under analysis/,
      with analysis/FINAL_ANALYSIS_CODE_MANIFEST.json mapping each result to its script, config,
      seed, package set and SHA-256 (this describes the state at FINAL_V3.2; analysis/ was later
      removed from the repository in v1.5.0 as study-specific material, and lives at the v1.4.0
      tag and in that release's deposited archive);
  B2  synthetic dose voxels can no longer enter a production dosiomics pathway;
  B3  the release candidate and Zenodo package are rebuilt from the current commit;
  B4  the two unfilled placeholders in the draft report are resolved from the manifest.
